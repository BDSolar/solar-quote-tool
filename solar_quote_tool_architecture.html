1. High-Level Architecture

The Solar Quote Tool is a vanilla JavaScript single-page application hosted on GitHub Pages. It uses Supabase as a backend for data storage (PostgreSQL with REST API) and Edge Functions for user management. There is no build step or framework — just static HTML, CSS, and JavaScript files.

Key Components

Frontend (GitHub Pages)

  • index.html — The main quote builder interface where users configure solar systems
  • admin.html — Administrative interface for managing contractors, pricing, and users
  • guide.html — Interactive user guide with screenshots and field-level documentation
  • app.js (~4,200 lines) — Core quote logic including calculations, UI population, and PDF generation
  • admin.js (~1,500 lines) — Admin panel logic for contractor, pricing, and user management
  • config.json — Structural rules, CEC tables, STC zone definitions, mounting calc rules, battery rules
  • style.css — Shared styling across all interfaces

Supabase Backend

  • Product Pricing Tables (10) — panels, inverters, battery_modules, gateways, ev_chargers, accessories, battery_mounting, mounting_kits, mounting_parts, addons
  • Reference Tables — battery_packages, solax_bms_components, business_params
  • Operations Tables — quotes, reps, contractors, rate_card_items
  • Edge Functions — admin-users (list/create/delete auth users via service_role key, deployed with --no-verify-jwt)

External APIs

  • Google Maps JavaScript API — Places Autocomplete for address input (quote tool + admin)
  • Google Distance Matrix API — Auto-calculates driving distance from contractor to install site
  • supabase-js v2.98.0 — Database client (SRI-pinned)
  • jsPDF + AutoTable — PDF generation (SRI-pinned)
All CDN scripts are pinned with SRI (Subresource Integrity) hashes for security. RLS policies cover both anon and authenticated roles on all admin tables.

Parallel Initialization

All four tasks run concurrently on DOMContentLoaded:

  • loadConfig() — Fetches config.json + 12 parallel Supabase queries, then calls reconstructConfig()
  • loadReps() — Populates the sales rep dropdown
  • loadContractors() — Loads contractor list, restores saved selection from localStorage, calls loadRateCard()
  • initAutocomplete() — Dynamically loads Google Maps JS API, attaches Places Autocomplete to the address field

Config Merge

reconstructConfig(baseConfig, tables, batteryPackages, bmsParts, businessParams) merges database pricing into the structural config from config.json, producing a single CONFIG object used by all calculations.

Fallback Chain

  • 1. Supabase DB — Primary source (live pricing)
  • 2. config.json — Secondary if DB fails (may have prices)
  • 3. DEFAULT_CONFIG — Embedded in app.js as last resort

Google Places Integration

On address selection, the autocomplete handler:

  • Splits address_components into Street / Suburb / State / Postcode
  • Calls updateZoneDisplay() to set STC zone
  • Calls calculateTravelDistance() — uses Distance Matrix to compute driving km from contractor's address
  • Shows a yellow warning if distance exceeds the contractor's service_region_km

3. The calculateQuote() Engine

This is the core pricing engine that runs whenever the user changes any input. It reads form state, optimizes battery configurations, validates against CEC requirements, and calculates the final price.

Trigger & Debounce

User actions trigger calculateQuote(). Text inputs are debounced by 150ms. Dedicated controls (dropdowns, steppers) fire immediately on change.

Calculation Steps

1. syncStateFromDOM() — Reads 20+ form fields into a state object. Reads admin-set values: state.deemingPeriod (from dropdown) and state.batteryStcFactor (STC factor for battery rebate).

2. Battery Optimization (one of three paths):

  • optimizeDualStack() — For Sigenergy systems over 48kWh, splits into 2 stacks with separate inverters
  • optimizeParallelBattery() — For SolaX systems exceeding single-stack capacity
  • optimizeBattery() — Standard path: finds cheapest module combination to reach target kWh

3. autoSelectInverter() — Picks appropriate inverter if user hasn't manually selected

4. checkCec() — Validates inverter + panel combination against CEC-approved list

5. calculateMountingKits() — Calculates roof kits, rails, tilt frames, kliplock, surcharges

6. Installation Costs:

  • If contractor selected: calculateInstallationCosts() uses rate card with condition matching via buildQuoteContext()
  • If no contractor: Falls back to $/kW + $/stack rates from business_params

7. Product Discounts:

getEffectivePrice(product) returns discounted price if within the product's discount_from/discount_to date range, else the base price. Applied to panels, inverters, battery modules, gateways, EV chargers, and accessories.

8. Final Price:

Equipment + Mounting + Installation + GP Margin + Commission - PV STC Rebate - Battery Rebate, then × 1.1 for GST.

9. Post-GST Adjustments:

  • Fixed Overhead — Flat dollar amount from business_params.fixed_overhead, added after GST. Not visible in quote UI or BOM.
  • Zero Bill Premium — MAX(zero_bill_base, priceBeforeRebatesIncGst × zero_bill_pct / 100). Applied only when "Zero Bill" quote type is selected.
  • Discount — Quote-level dollar deduction entered by the rep.

Sigenergy

  • Gateway dropdown — Selects backup protection device
  • Scope toggle (Partial / Full Home) — Segmented button to the right of the gateway dropdown, always visible but disabled when no gateway is selected
  • When gateway is selected, onBackupScopeChange() fires automatically, adding the appropriate board upgrade addon

SolaX

  • Backup Options toggle (None / Partial / Full Home) — Three-option segmented button, appears when batteries are configured
  • onSolaxBackupChange() handles addon swap and circuit count
  • Full Home additionally triggers getSolaxEpsBoxCost() for EPS box auto-add on X3-Hybrid inverters

Board Upgrade Addons

Both addons are pricing_type: 'quoted' — the rep enters a custom dollar amount. They are matched by label in currentRateCardItems:

  • Partial → "Partial board upgrade" + 3 backup circuits
  • Full Home → "Meter board upgrade" + 5 backup circuits

Switching scope/option automatically removes the old addon and adds the new one. If the contractor's rate card doesn't have the matching item, the addon step is skipped gracefully.

5. STC Rebate — Date-Aware Transition

The STC rebate system automatically transitions on 1 May 2026 with no admin action required.

STC Rebate Logic
flowchart TD
    Admin["Admin Business Parameters"]

    Admin --> PVDeeming["PV Deeming Period
(dropdown by year, e.g. 5 for 2026)"]
    Admin --> BatFactor["Battery STC Factor
(e.g. 8.4, declines every 6 months)"]
    Admin --> StcPrice["STC Price (e.g. $37)"]

    PVDeeming --> PVReb["PV STC Rebate
floor(kW × zone × deeming) × stcPrice"]
    BatFactor --> BatReb["Battery STC Rebate
floor(tiered_kwh × factor) × stcPrice"]
    StcPrice --> PVReb
    StcPrice --> BatReb

    BatReb --> Tiers{{"After May 1 2026?"}}
    Tiers -->|"Before"| Flat["Flat: kWh × factor"]
    Tiers -->|"After"| Tiered["Tiered:
0-14 kWh @ 100%
14-28 kWh @ 60%
28-50 kWh @ 15%"]

    PVReb -.->|"Urgency banner"| Banner["getNextStepDown()
Compares current price vs
next scheduled reduction"]
    BatReb -.-> Banner

Key Functions

  • calcBatteryRebate(usableKwh, stcFactor, stcPrice) — Calculates battery rebate using admin-set factor; applies tiers from May 2026
  • calcBatteryRebateTiered(cappedKwh, stcFactor, stcPrice) — Tiered STC structure with configurable factor
  • getNextStepDown(currentDeeming, currentFactor) — Finds next scheduled reduction from hard-coded PV/battery schedules for urgency banner
PV deeming period and battery STC factor are admin-controlled via Business Parameters. The urgency banner uses hard-coded published schedules to compare current price against the next step-down. Banner auto-hides when no future step-down exists.

The app supports saving quotes to Supabase, loading them back, and generating PDF documents.

    JS->>DOM: Full UI updated

    Note over U,SB: GENERATE PDF

Save Quote

  • collectQuoteData() gathers: customer, system (incl. backupScope, solaxBackupType, quoteType), mounting, pricing, installation, totals
  • BOM Snapshot — buildBOM() output saved at root of quote JSONB. Format: [{category, items: [{desc, sku, qty, unit, total, supplier_code}]}]
  • Product Discounts — collectActiveDiscounts() snapshots any active promotional discounts at save time
  • Additional totals: priceBeforeRebatesIncGst, pvStcCount, installTotal, discount, zeroBillPremium, fixedOverhead

Load Quote

  • Restores system type and manufacturer first, then repopulates all dropdowns
  • Restores backup scope (Sigenergy) and backup options (SolaX) — maps old whole_home values to full for backwards compatibility
  • Loads contractor rate card with skipCalc flag to prevent premature calculation
  • checkExpiredDiscounts() compares saved discount snapshots against current prices — shows yellow warning banner if they've changed

Generate PDF

  • Dark-themed PDF with system summary bar (panels, battery, inverter, backup type)
  • Itemized BOM grouped by category
  • Zero Bill Premium shown as line item if applicable
  • SolaX backup type (Partial/Full Home) and Sigenergy gateway shown in summary

BOM (Bill of Materials)

The BOM is always accessible from the toolbar (no auth required) and is built client-side by buildBOM(). It includes every component, SKU, quantity, and cost. In the admin panel, showQuoteBOM(idx) renders a fully-costed BOM overlay with print support for saved quotes.

Contractors Mode

  • loadContractors() — Lists all contractors with search/filter

  • Details Tab: Business info, address (with Google Places autocomplete), licenses, compliance dates, travel threshold (default 80 km), service region
  • Rate Card Tab: 28 default items, conditions editor, inline price editing
  • seedDefaultRateCard() — Creates 28 standard rate card items for new contractors

Pricing Mode

  • loadPricingData() — Runs same 12 parallel queries as app.js
  • Filter by category (panel, inverter, etc.) and manufacturer
  • Product tables with inline price editing, active toggle, sort order

Business Params: GP margin, commission, STC price, install rates, fixed overhead, zero bill base/percentage, battery rebate per kWh

Bulk Import: Paste CSV data, match supplier codes across all tables via buildSupplierCodeLookup(), batch update prices

Users Mode

  • Lists authenticated users via the admin-users Edge Function
  • Create new users (email + password)
  • Delete users
  • Edge Function uses Supabase service_role key for admin operations

Product Discounts

Six tables support promotional discounts: panels, inverters, battery_modules, gateways, ev_chargers, accessories. Each has discount_pct, discount_from, discount_to columns. Active discounts show as green badges in admin table rows via discountBadge() / isDiscountActive().

Configuration Tables (feed into CONFIG object)

  • business_params — Margins, STC price, install rates, fixed overhead, zero bill settings, battery rebate rate
  • panels — Panel specifications and prices (+ discount columns)
  • inverters — Inverter specifications and prices (+ discount columns)
  • battery_modules — Battery specifications and prices (+ discount columns)
  • gateways — Gateway specifications and prices (+ discount columns)
  • ev_chargers — EV charger specifications and prices (+ discount columns)
  • accessories — Accessory specifications and prices (+ discount columns)
  • addons — Add-on definitions and pricing
  • battery_mounting — Battery mounting prices
  • mounting_kits — Mounting kit prices
  • mounting_parts — Individual mounting part prices
  • battery_packages — SolaX bundle pricing
  • solax_bms_components — BMS and series box costs

Discount Columns (6 tables)

panels, inverters, battery_modules, gateways, ev_chargers, and accessories each have:

  • discount_pct (numeric) — Percentage discount
  • discount_from (date) — Start of promotional period
  • discount_to (date) — End of promotional period

Operations Tables

quotes

  • id (uuid) — Primary key
  • data (jsonb) — Full quote data including customer, system, mounting, pricing, installation, totals, bom_snapshot, custom_addons, discounts
  • rep_id (uuid) — References reps table
  • created_at (timestamp)

contractors

  • id (uuid) — Primary key
  • business_name (text)
  • address (text) — Origin for travel distance calculation
  • travel_threshold_km (numeric) — Free km before travel charges (default 80)
  • service_region_km (numeric) — Warning limit for service area
  • active (boolean)
  • Has many rate_card_items

rate_card_items

  • id (uuid) — Primary key
  • contractor_id (uuid) — References contractors
  • label (text) — Display name (e.g., "Partial board upgrade")
  • category (text) — e.g., 'installation', 'electrical'
  • input_type (text) — standard, checkbox, addon, auto
  • pricing_type (text) — per_watt, per_panel, per_metre, per_circuit, per_km, flat, quoted
  • threshold_type (text) — 'after' for per_km items (charges beyond threshold)
  • rate (numeric) — The price value
  • threshold (numeric) — Threshold value for per_metre/per_km items
  • conditions (jsonb) — Matching rules (e.g., {"has_backup": true})
All admin tables have RLS enabled with policies for both anon and authenticated roles. When adding new tables, always add policies for both roles.
